Recipe Saver — how it works

In plain words: Recipe Saver is a small recipe book that lives entirely on your computer. The page you see in your browser (the program you are reading this in — Chrome, Safari, Firefox) is the table: a form, a list, a search box. Behind it, a small program called the server (the program that listens for requests and answers them) is the kitchen: it checks every recipe you save and keeps the book. The book itself is one file, recipes.json. Every click you make travels from the table to the kitchen and an answer travels back — and that loop is the whole app.

Every file in your project, one human sentence each — including what would happen if it went missing:

recipe-saver/
├── server.js        → the kitchen — starts with: node server.js. Delete it and nothing answers;
│                      the page never loads.
├── public/          → the table and menu — everything your browser shows you
│   ├── index.html   → the page itself: the form, the search box, the list.
│   │                  Delete it and the browser shows an error instead of a page.
│   ├── app.js       → the waiter — carries your clicks to the kitchen and brings answers back.
│   │                  Delete it and the page loads, but nothing happens when you click.
│   └── style.css    → the decor — colors, fonts, spacing.
│                      Delete it and everything still works, just ugly.
├── recipes.json     → the recipe book — every recipe you ever saved, one page per recipe.
│                      Delete it and the app still runs, with an empty book. This file is
│                      the only place your recipes exist — copy it somewhere safe if you love them.
├── package.json     → the label on the box — the app's name and its one start command.
└── README.md        → the note you (or your AI) left for future you.

Words you'll hear

Every technical word this document used, in the order you met it:

browser
The program you are reading this in — Chrome, Safari, Firefox. It opens pages and talks to servers for you.
server
The program that listens for requests and answers them. Yours is server.js, and it runs on your own computer, not on the internet.
page / front end
Everything you can see and click: the form, the list, the search box. The files in public/. "Front end" is simply the tech name for "the part you see".
request / response
One trip: a question your page sends to the server, and the answer that comes back. Every click silently sends one.
API
The kitchen's service window: the fixed menu of messages the server understands. Your kitchen understands three — show me the recipes, save this recipe, search for this word — written as the /api/... addresses you may spot in the code.
JSON
"Jason" — the plain-text grammar for writing little labeled forms, the one you saw inside a saved recipe. The whole book, and every message between page and kitchen, is written in it.
localhost / port
Your own computer's nickname in the browser. http://localhost:3000 means "this same machine, door number 3000" — the port is just a numbered door, and the kitchen listens at door 3000.
validation
The kitchen's quality check before cooking: "does this recipe have a title?" The polite red error you saw is validation talking.
unique id
A made-up tag, long and random, that no two recipes share — like a raffle ticket stapled to each page of the book.
400 and 404
The kitchen's numbered ways of saying no. 404: "never heard of that dish" (wrong address). 400: "this order doesn't make sense" (something was missing or unreadable).

How to explain it to a friend

"Recipe Saver is a digital recipe book that lives on my computer. A page in my browser is the table, a small program called the server is the kitchen, and a single file is the book. When I save a recipe, the kitchen checks it, glues it into the book, and reads the whole book back to my page. When I search, the kitchen flips through every page and serves up only the matches. Nothing goes online — it's all mine."
